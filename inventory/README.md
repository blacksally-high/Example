# 재고온 · 개인용 재고관리 프로그램

품목, 입출고, 안전재고와 발주 기준을 한곳에서 관리하는 한국어 웹 프로그램입니다.

## 1. 프로젝트 개요 및 디렉터리 구조

HTML/CSS/JavaScript로 동작하며 외부 라이브러리, API 키, 서버 데이터베이스가 필요 없습니다. 실제 데이터는 현재 웹사이트 주소의 브라우저 localStorage에 저장됩니다. 예시 데이터 체험 모드는 메모리에서만 동작하므로 실제 데이터와 섞이지 않습니다.

| 경로 | 역할 |
|---|---|
| `dist/index.html` | 프로그램 진입 화면 |
| `dist/styles.css` | 반응형 한국어 화면 스타일 |
| `dist/core.js` | 재고 산식, 검증, CSV 처리 |
| `dist/app.js` | 화면, 품목·입출고, 가져오기·백업 |
| `dist/README.md` | 화면에서 내려받는 사용 안내 |
| `dist/재고온_소스코드.zip` | 배포 시 제공하는 전체 소스 압축파일 |
| `tests/core.test.js` | 계산·검증 자동 테스트 |
| `scripts/serve.js` | 로컬 실행 서버 |
| `scripts/package.py` | 전체 소스 ZIP 재생성 |
| `package.json` | 실행·검증 명령 및 환경 명세 |
| `.gitignore` | 민감 파일·백업·개발 산출물 제외 |
| `../.github/workflows/inventory-pages.yml` | 검사 후 GitHub Pages 배포 |

## 2. 필수 설정 파일과 실행

권장 환경: Node.js 22 이상, 최신 Chrome / Edge / Firefox. Python 3은 소스 ZIP 재생성 시에만 필요합니다. npm 의존성은 없으므로 `npm install`은 필요하지 않습니다.

ZIP을 압축 해제한 뒤 터미널에서 프로젝트 폴더로 이동합니다.

```bash
cd jaegoon-inventory
npm start
```

브라우저에서 `http://localhost:8080`을 엽니다. 종료는 터미널에서 Ctrl+C입니다. Windows에서도 같은 npm 명령을 사용할 수 있습니다. `dist/index.html`을 직접 열 수도 있지만 파일 URL의 저장 정책은 브라우저마다 다르므로 로컬 서버 또는 배포된 주소를 권장합니다.

```bash
npm test
npm run check
# 소스를 수정한 뒤 다운로드 ZIP 재생성 (Python 3 필요)
npm run package
```

`.gitignore`는 `.env`, `node_modules`, 백업 폴더 등을 제외합니다. 이 버전은 인증키를 요구하지 않습니다. 나중에 외부 API를 연동할 경우 비밀키를 프런트엔드에 넣지 말고 서버 환경변수로 관리하세요.

## 3. 핵심 기능과 사용 순서

1. **예시 데이터 체험**: 대시보드 버튼으로 가상 품목 8개를 확인합니다. 체험 중 변경은 저장되지 않습니다. `내 데이터로 돌아가기` 또는 새로고침으로 종료합니다.
2. **품목 관리 → 품목 등록**: 품목코드(SKU), 품목명, 단위, 초기 재고를 입력합니다. 분류·장소·거래처·단가는 선택 항목입니다. 코드는 대소문자를 구분하지 않고 중복을 차단합니다.
3. **품목별 기준 입력**: 일평균 출고량, 평균 리드타임, 안전재고 방식 및 해당 변수, 목표 보유일수를 입력합니다. 실제 값을 알 수 없으면 빈칸으로 두세요. 앱은 이력을 이용해 수요를 자동 추정하지 않습니다.
4. **입출고 등록**: 입고/출고 수량은 양의 정수입니다. 출고 수량이 현재고를 초과하면 차단합니다. 실사 조정은 최종 실사 수량과 조정 사유를 입력합니다. 이력은 삭제하지 않고 조정으로 정정합니다.
5. **발주 관리**: 입고 예정 수량을 반영한 제안을 확인합니다. 거래처에 실제 주문하는 기능은 없습니다. 발주 후 `품목 수정 → 입고 예정 수량`을 갱신하고, 입고 시 차감 옵션을 사용하세요.
6. **재고 분석**: ABC 등급, 보유일수, 불용 검토, EOQ를 확인합니다.
7. **백업 / 복원**: JSON으로 전체 데이터를 저장합니다. 복원은 현재 데이터를 교체하며 검증 및 확인 화면을 거칩니다. CSV는 품목 추가와 보고용입니다.

### 품목 정보와 수량

수량은 개·박스 등의 정수 단위입니다. kg/L 등 소수 재고는 이 버전에서 지원하지 않습니다. 일평균 출고량과 단가 등 계산 변수에는 소수를 사용할 수 있습니다. 현재고는 초기재고 및 모든 입출고 증감 합계입니다. 모든 기록은 등록 순서로 검증하며 과거 일자 입력은 표시용 업무일입니다. 과거 특정 날짜의 잔고 재구성 기능은 없습니다.

품목 수정에서는 기존 현재고를 직접 변경하지 않습니다. 입출고/실사 조정으로 변경해 이력을 남깁니다. 기록 보존을 위해 품목·이력 삭제 기능을 제공하지 않습니다. 등록 오류는 품목 정보 수정 또는 실사 조정으로 바로잡습니다.

### CSV 가져오기

사용자가 제공한 `품목_일괄등록_업로드용.csv`를 `dist/templates/`에 원본 그대로 포함했습니다. 품목 관리의 **업로드 양식** 또는 백업 / 복원의 **첨부 업로드 양식** 버튼으로 내려받습니다. 이 파일에는 입력된 품목 3개가 포함되어 있으므로 실제 사용 전 검토·교체하세요. 프로그램은 기존 짧은 열 이름과 첨부 양식의 별표·공백·한글 계산방식을 모두 인식합니다. 단가·수요 등이 빈 값인 품목은 빈 값으로 유지합니다. 자동으로 실제 재고에 등록하지 않으며, 사용자가 가져오기를 확인한 경우에만 추가됩니다.

`백업 / 복원 → CSV 양식`에서 열 이름을 포함한 빈 양식을 내려받습니다. Excel에서 UTF-8 CSV로 저장하세요. 필수 열은 `품목코드,품목명,현재고,단위`입니다. 선택 열은 양식에 포함되어 있습니다. 숫자 칸에는 천 단위 쉼표·통화기호 없이 숫자만 입력하세요. 계산방식은 `days` 또는 `max`이며 미입력 시 `days`입니다. 최종출고일은 `YYYY-MM-DD`입니다.

가져오기는 **신규 품목 추가 전용**입니다. 기존 코드와 중복되면 전체 가져오기를 중지하며 기존 데이터를 덮어쓰지 않습니다. 행 오류, 음수, 잘못된 날짜도 차단합니다. 검증 후 처음 5개 품목을 미리 보여주고 저장합니다. 10MB 이하 파일을 지원합니다.

내보내는 CSV는 Excel 호환 UTF-8 BOM을 포함합니다. 문자열의 선두 `=`, `+`, `-`, `@`는 수식 실행 방지를 위해 작은따옴표를 붙입니다. 동일 텍스트를 다시 가져올 때는 필요에 따라 이 보호 문자를 검토하세요. 수량 증감 등 실제 숫자는 그대로 내보냅니다.

## 4. 재고 기준 및 문서화

첨부된 물품관리·재고관리 기준설정 지침의 산식을 반영했습니다. 아래 정책은 자동 추천 또는 업무 설계 기준이며 사용자의 실제 업무 규정으로 확인된 값이 아닙니다.

| 항목 | 계산 / 판정 |
|---|---|
| 안전재고 · 일수 방식 | 올림(일평균 출고량 × 완충일수) |
| 안전재고 · 최대 방식 | 올림(max(0, 최대 일출고량 × 최대 리드타임 − 일평균 출고량 × 평균 리드타임)) |
| 발주점 ROP | 올림(일평균 출고량 × 평균 리드타임 + 안전재고) |
| 목표재고 | 올림(일평균 출고량 × 목표 보유일수 + 안전재고) |
| 재고 위치 | 현재고 + 입고 예정 수량 |
| 권장 발주량 | 재고 위치 ≤ 발주점일 때 max(0, 목표재고 − 재고 위치), 아니면 0 |
| 긴급 | 현재고 ≤ 안전재고 |
| 발주 필요 | 안전재고 < 현재고 ≤ 발주점 |
| 정상 | 발주점 < 현재고 ≤ 목표재고 |
| 과잉 | 현재고 > 목표재고 |
| 확인 필요 | 안전재고·발주점·목표재고 중 하나라도 계산 불가 |
| 보유일수 | 현재고 ÷ 일평균 출고량 (출고량 0/미입력 시 계산 안 함) |
| EOQ | 올림(√(2 × 연간 수요 × 1회 발주비 ÷ 단위당 연간 보유비)) |
| 불용 검토 | 현재고 > 0이고 마지막 출고/관찰 시작 이후 설정 기간 이상 경과 |

품목별 변수는 임의 기본값으로 채우지 않습니다. 입고 예정이 비어 있으면 예정 없음(0)으로 처리합니다. 보유비 0 또는 EOQ 필수 값 누락 시 EOQ는 계산하지 않습니다. EOQ는 일정한 수요와 리드타임 등 가정을 가진 참고치이며 실제 발주 제안 수량으로 사용하지 않습니다.

ABC는 `일평균 출고량 × 30 × 단가`의 **월 추정 출고금액** 내림차순으로 계산합니다. 실제 매출 분석이 아닙니다. 초기 경계는 A 80%, B 95%, C 나머지이며 설정 화면에서 바꿀 수 있습니다. 각 품목을 더하기 **전**의 누적 비중으로 분류하여 경계를 넘기는 품목은 앞 등급에 포함합니다. 값 누락 품목은 제외하고 합계가 0이면 등급을 매기지 않습니다. 동률은 내부 ID 순서로 정렬합니다.

불용 검토 초기 정책은 90일이며 변경 가능합니다. 출고 기록 또는 입력된 최종 출고일 중 최신 날짜를 사용하고, 둘 다 없으면 품목 등록일을 관찰 시작일로 사용합니다. 입고만으로 관찰 기간을 초기화하지 않습니다. 불용 표시는 폐기 지시가 아닙니다.

초기 운영 제안: A등급과 긴급 품목은 매일, B는 매주, C는 매월 검토하고 업종에 맞게 조정하세요. 미입력·불용 검토 품목은 실제 수요와 보관 상태를 확인한 뒤 판단하세요.

### 기술 스택과 범위

- HTML5 / CSS3 / JavaScript / localStorage
- Node.js 내장 HTTP 서버와 `node:test`
- GitHub Actions / GitHub Pages 배포 설정
- 외부 런타임 의존성 없음

기기·브라우저·사이트 주소가 달라지면 저장 데이터가 별개입니다. 여러 사용자 동시 공유, 서버 자동 백업, 사용자 권한, 바코드, 유통기한/로트, 창고 간 이동 전표, 실발주·외부 ERP 연동은 제공하지 않습니다. 여러 창의 덮어쓰기를 감지하면 새로고침을 요청합니다. 업무 데이터는 주기적으로 JSON으로 백업하세요.

## 5. 이 저장소에서 실행·수정하기

이 프로그램은 `blacsally/Example` 저장소의 `inventory/` 하위 폴더에 있습니다.

```bash
git clone https://github.com/blacsally/Example.git
cd Example/inventory
npm start
```

브라우저에서 `http://localhost:8080`을 엽니다. 웹 배포 주소는 GitHub Actions의 배포 결과에서 확인하세요.

소스 수정 후:

```bash
npm test
npm run check
npm run package
git add .
git commit -m "feat: 재고관리 기능 개선"
git push origin main
```

## 6. GitHub Pages 배포

저장소 루트의 `.github/workflows/inventory-pages.yml`이 `main` 변경 시 테스트·문법 검사 후 사이트를 배포합니다. 배포 파일은 `_site/inventory/`에 준비되며, 실행 경로는 `/Example/inventory/`입니다. 루트 홈페이지에는 프로그램 바로가기가 표시됩니다.

최초 1회 저장소 `Settings → Pages → Build and deployment → Source`에서 **GitHub Actions**를 선택해야 할 수 있습니다. Actions 실행 결과가 성공인지 확인하세요. 프로그램 소스를 다른 저장소로 복사할 때도 루트 워크플로를 함께 옮겨야 합니다.

이 저장소는 공개 저장소입니다. 실제 재고 데이터와 백업 파일은 올리지 마세요. 앱은 서버로 재고 데이터를 전송하지 않으며 사용자의 현재 브라우저에만 저장합니다. 기존 비공개 사이트와 GitHub Pages는 주소가 다르므로 데이터가 자동 이동하지 않습니다. 필요한 경우 기존 사이트에서 JSON 백업 후 새 사이트에서 복원하세요.

GitHub 공식 문서(2026-10-28 확인):
https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
