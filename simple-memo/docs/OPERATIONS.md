# 운영·백업·복구

## 계정과 서비스

GitHub 인증 사용자 `blacksally-high`와 Example 저장소의 쓰기 권한을 실제 조회했습니다. 독립 `simple-memo` 저장소는 조회되지 않았습니다. Supabase 프로젝트 `simple-memo`의 ID는 `nslhhczdyfqlwhxqsplw`, 조직 ID는 `xbsefadxxdoecilgqdqd`, 지역은 서울입니다. 프로젝트 소유 계정의 이메일은 조회 도구로 확인할 수 없었습니다.

기존 메모 테이블과 기존 GitHub Pages 프로그램은 유지했습니다. 신규 데이터는 `memo_notes`에 저장합니다. 과거 앱의 데이터가 있다면 별도의 검토된 이전 작업이 필요합니다.

## 데이터·저장 설계

- 사용자별 IndexedDB 키: `[user_id, note_id]`. 기기 모드 owner는 `device`입니다.
- 실제 입력마다 로컬 쓰기를 순서대로 처리하고, 조합 입력 종료 후 약 800ms 지연으로 서버 전송합니다.
- 메모 UUID와 작업 UUID를 사용합니다. 서버는 마지막 작업 ID의 반복 요청을 같은 결과로 돌려줍니다.
- 버전 불일치에서는 덮어쓰지 않고 충돌 상태로 전환합니다. 사용자는 두 내용을 확인하고 내 변경을 새 메모로 보관할 수 있습니다.
- 클라우드 API의 쓰기는 원자적 버전 검사 함수에 한정합니다. 일반 인증 역할은 테이블 직접 쓰기 권한이 없습니다.
- `memo_save`, `memo_remove`는 의도적으로 제한된 SECURITY DEFINER API입니다. 모든 경로에서 실제 사용자 존재·행 소유권을 확인하며 search_path를 비우고 PUBLIC/anon 실행을 금지합니다. Supabase 보안 검사 경고 2건은 이 의도된 구조에 대한 검토 대상으로 문서화했습니다. 추가 보안 검토와 실제 A/B 계정 API 검증은 필요합니다.
- 빈 메모 및 20,000 코드 포인트 초과 내용은 서버 전송하지 않습니다. JS Array.from과 Postgres char_length를 사용합니다. 결합 이모지는 여러 코드 포인트로 계산할 수 있습니다.
- 서비스 워커는 앱 셸만 캐시합니다. 인증·메모 API 응답은 캐시하지 않습니다. 새 워커를 강제 활성화하지 않아 입력 중 갱신으로 초안을 제거하지 않습니다.

## 사용자 백업

설정 → 전체 메모 내보내기로 JSON을 보관하세요. 온라인 계정 모드에서는 페이지를 끝까지 조회한 뒤 로컬 미전송 변경을 합칩니다. 오프라인에서는 캐시된 범위만 내보내며 파일 scope에 `cached-only`를 표시합니다.

복원은 최대 20MB·5,000개·메모당 20,000 코드 포인트를 검사하며 다른 계정의 ID/소유권은 사용하지 않습니다. 새 UUID로 추가하고 원래 작성 시각을 imported_created_at에 보관합니다. 한 가져오기 작업의 재시도는 동일 메모 UUID를 사용합니다.

## 운영자 백업

사용자 JSON 파일은 운영 데이터베이스 백업을 대체하지 않습니다. 현재 요금제의 백업 가용성, 주기와 보존기간을 확인하지 못했으며 일일 백업을 설정했다고 주장하지 않습니다. Supabase Dashboard에서 실제 백업 정책과 비용을 확인한 뒤 구성해야 합니다. 복원은 별도의 승인된 테스트 프로젝트에 수행해야 하며 운영 DB를 복원 테스트 대상으로 사용하지 마세요.

복원 검증 순서: 스냅샷 확보 → 분리된 DB에 복원 → 스키마·행 수·소유권·메모 본문 비교 → A/B 권한 확인 → 결과 기록. 이번 작업에서 이 복원은 수행하지 않았습니다.

## 인증 출시 조건

1. 사용자 지정 SMTP·발신 도메인·발신 주소를 실제 계정에서 구성합니다.
2. 실제 배포 URL과 비밀번호 재설정 경로를 Supabase Auth 리디렉션 허용 목록에 등록합니다.
3. 팀 외부 주소로 확인·재발송·재설정·재로그인을 테스트합니다.
4. 속도 제한·남용 방지를 점검합니다. 필요한 CAPTCHA는 별도 발급 및 키 설정이 필요합니다.
5. 운영자 명칭·연락처·정책·장애 경보 수신자를 확정합니다.
6. 계정 삭제 서버 배포 승인을 받고 보안·실제 통합 테스트를 완료합니다.
7. 검증 결과표의 출시 차단 항목을 해결한 뒤에만 공개 회원가입 플래그와 사이트 공개 범위를 변경합니다.

이메일 확인을 끄는 우회 설정은 하지 않았습니다. 결제나 신규 유료 서비스 계약도 진행하지 않았습니다. 실제 요금과 쿼터는 사용자의 기존 요금제를 확인해야 합니다.

## 계정 삭제 코드 주의

`supabase/functions/memo-delete-account/index.ts`는 아직 배포되지 않은 검토용 코드입니다. 요청 토큰 getUser와 현재 비밀번호 재인증을 사용하고, 관리자 키는 서버 환경에서만 읽습니다. 다른 프로젝트로 복사하기 전에 데이터 삭제 범위·인증 제한·실패 시 재시도·세션 폐기·백업 보존 정책을 검증해야 합니다. 운영 데이터에 대한 시험 삭제는 하지 마세요.
